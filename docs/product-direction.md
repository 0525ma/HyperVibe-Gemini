# HyperVibe 产品定义与研发方向（2026-09-26 草案）

## 产品定位

HyperVibe 面向需要在 Mac 上频繁切换应用、输入文字与操控界面的用户，把手边的 Siri Remote 变成可编程输入设备。语音能力的核心任务是在当前光标处可靠地产生文字；按键映射、光标控制和语音反馈共同服务于这一任务。

当前可验证的能力来自仓库代码：遥控器按键映射、按应用配置、层、触控板指针、麦克风采集、转写、选区改写和文本投递。语音识别效果、远程麦克风可靠性、真实用户留存和付费意愿尚无本项目的量化证据，不作为对外承诺。

## 本轮范围

把原生语音转写的必需凭据和两条音频请求链路由 OpenAI 改为 Gemini：完整录音调用音频转写模型；流式输入调用 Live 转写模型。DeepSeek 与 OpenAI 继续作为可选的文字整理、选区改写服务。保留原来的录音来源选择、个人词典、焦点保护、失败时复制、快捷键模式和其他遥控器功能。

本轮不更换麦克风硬件，不承诺离线转写，不把 Gemini Key 写入公开配置、仓库或日志。用户须在应用设置中输入自己的 Gemini API Key。

## 验收门槛

| 场景 | 通过条件 | 证据 |
| --- | --- | --- |
| 凭据 | Gemini Key 在设置中保存；模型查询与真实转写请求分别通过，无 Key 或无配额时给出明确提示 | 设置界面状态、合成音频 API 测试与脱敏诊断 |
| 完整转写 | 1 秒以上普通话和中英混说，松键后获得非空文字并投递到原光标 | 录屏、目标文本与阶段延迟 |
| 实时转写 | 按住说话时预览更新，已确定片段才进入编辑器；松键后结果无重复、无丢尾 | 目标文本与服务端最终片段对照 |
| 故障回退 | 网络断开、无权限、无效 Key、目标焦点变化时不误写其他应用；必要时复制结果 | 故障注入记录 |
| 安全与交付 | 源码通过测试与构建，签名保持稳定；安装后仅一个运行实例 | 测试摘要、签名验证、进程路径 |

目前前三项需要用户自有 Gemini Key 和实机语音验证。构建通过只证明代码可编译，不能替代转写验收。

2026-09-27 发现：当前账号的 Key 可查询模型，但合成普通话音频调用专用转写模型和普通 Gemini 音频模型均返回配额类错误。这个结果只说明当前项目/时间窗口无法完成调用，需在 Google AI Studio 核对该 Key 所属项目的模型限额与使用量；不能把设置页“已连接”当作转写通过。

## 迭代方向

1. **P0 可用性**：完成 Gemini 实机转写与延迟测量；把认证、配额、网络和模型不可用错误分开显示；保持失败时的录音重试与文字复制通路。
2. **P1 体验**：按普通话、中英混说、技术词、远近麦克风四组场景建立对照样本；记录转写成功率、首字延迟、松键到文字延迟、重复/漏字率，并根据数据优化词典和音频采集。
3. **P2 可维护性**：抽象转写 provider 接口，让 Gemini、其他云服务或本地模型按能力接入；将凭据存储、模型能力和错误映射纳入回归检查。只有在 P0 稳定后再评估离线方案。

每个阶段以真实目标应用与设备端结果验收。上线、分享和客户交付另设签名、权限、安装与回滚门槛。
